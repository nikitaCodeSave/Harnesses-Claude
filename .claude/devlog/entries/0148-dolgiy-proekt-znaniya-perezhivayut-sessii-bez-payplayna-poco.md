# Долгий проект: знания переживают сессии без пайплайна Pocock

## Контекст

Оператор уточнил после #147: разработка идёт месяцами, агенту нужен контекст
проекта, а не первичное обсуждение задачи, и подход Pocock ценен именно этим —
несмотря на цену. Основные матрицы мерили задачи в одну сессию, где слою знаний
окупиться негде, так что вывод «Pocock не по умолчанию» был обобщён шире данных.
Поставлен многосессионный стенд: проект L1 (библиотека) растёт через три фичи
в новых сессиях; владелец на каждую фичу стартует без памяти, решения «на
будущее» называет один раз в ранней фиче и больше не повторяет; отдельный
скрытый оракул `test_cross` проверяет, что поздние фичи их соблюдают. Плечи:
S — спина без слоя знаний; K — спина + лёгкие правила `GLOSSARY.md`/ADR в
`CLAUDE.md`; PL — поток Pocock (`grill-with-docs` → `to-spec` → `to-tickets` →
`/implement` по тикету в свежей сессии, без `tdd`). Гипотезы — в README до
сборки фикстуры.

## Результат (`RESULTS.md`)

`test_cross` 100%: S 3/3, K 3/3, PL 2/3. Стоимость: S $3.9, K $4.6, PL $43.7
(в 11 раз дороже S), ходов человека 3 / 3 / 16. HL1 не подтверждена — передовая
модель сама записала решения «на будущее» в долговременный файл (раздел спеки
или `ROADMAP.md`), пронесла их через перезапись спеки и прочитала позже. HL2
выполнена — лёгких правил достаточно. PL-3 потерял одно решение: его не было в
ADR, и при нарезке на тикеты в свежих сессиях оно выпало — тот же механизм, что
у плеча F в #147. Дым на haiku (n=1, вне правил): S 8/19, K 18/19 — на слабой
модели привычки нет, правила её дают.

## Решения и изменения

- Долгий проект: спина + лёгкие правила знаний в проектном `CLAUDE.md` (термины
  в `GLOSSARY.md`, решения включая «на будущее» — в ADR в той же сессии, читать
  перед работой) как страховка, не зависящая от привычки модели.
- Инструменты Pocock — по триггеру: фича больше сессии (`/to-spec` →
  `/to-tickets`, трекер, `/implement` по тикету с исполнимыми критериями),
  туман (`/wayfinder`), язык домена складывается (`/grill-with-docs`, опционально),
  после вехи (`/retro`). Полный пайплайн на каждую фичу — не по умолчанию.
- Установка Pocock — плагином `mattpocock-skills` с маркетплейса
  `mattpocock/skills`; `/tdd` закрыт deny-правилом `Skill(mattpocock-skills:tdd)`
  (проверено: `skillOverrides` на скиллы плагинов не действует). Прямую установку
  в `~/.claude` классификатор заблокировал — команды переданы оператору.
- `workflow.md` § Долгий проект переписан под замер; `principles.md`,
  `WORKFLOW.md`, `README.md` согласованы; в `kit-handoff.patch` добавлены правила
  знаний.

## Урок

Ценность, которую оператор приписывал пайплайну (контекст между сессиями), на
этом стенде давал не пайплайн, а запись решений в файл — дешёвое действие,
которое передовая модель делает сама, а правило делает надёжным. Полезные
свойства Pocock, которые стенд не видит (трекер как состояние работы, карта
решений, retro), остаются в потоке по своим триггерам.

## Открыто

Месяцы накопления — десятки фич и решений, разрастание одной спеки — не
моделировались: там структура ADR вероятнее окупается. Кандидат в следующий
стенд, не правило.
