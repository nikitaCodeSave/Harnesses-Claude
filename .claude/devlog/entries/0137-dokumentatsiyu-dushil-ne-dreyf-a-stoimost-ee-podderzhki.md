# Документацию душил не дрейф, а стоимость её поддержки

## Контекст

Оператор принёс наблюдение из `Greenplun-router-runtime`: харнесс порождает остаточные
артефакты, они перерастают в правила, правила быстро устаревают и душат разработку, а
уследить за ними невозможно — при том что Claude Code достаточно одного источника истины,
кода. Проверка на фактах подтвердила итог и **опровергла названный механизм**, и разница
между ними определила правку.

## Замер

| | |
|---|---|
| markdown | 848 файлов, 63 677 строк |
| код | 100 811 строк |
| тесты | 75 файлов, 35 033 строки, 1679 passed |
| devlog | 400 записей за месяц, пик 45 за день |
| коммиты, трогающие только `.md`/`.json` | **759 из 1369 — 55%** |

## Опровергнутая гипотеза: доки не устарели

Прогон по битым ссылкам дал 30 «MISSING», из которых почти все — ложные негативы метода
(пути вида `runtime/`, `sources/cp/` относительны к `src/app/`). Живой слой оказался
аккуратным и **честным относительно удалённого**: `eval/golden.py` подписан «Legacy-стек
удалён», `federation/` — «There is no legacy federation/», `docs/gates/` — «создаётся
заново, когда появится». Единственный dangling в STATUS.md помечен «historical».

Настоящий дрейф нашёлся в другом месте и другого рода: `src/app/sources/cp/PROVENANCE.md`
четырежды ссылается на ADR-секции `docs/ARCHITECTURE.md` («cp: отказ на точечный остаток»,
«cp: shape-бэкстоп активности», «cp: детектор инверсии направления», «cp: гигиена name-LIKE
литералов»), которых в том файле нет и не было. Проектный `check_project_tracking.py` их не
ловит: он валидирует markdown-ссылки, а это текст в бэктиках. Метод чекера проверен
инъекцией заведомо битой ссылки — `BROKEN_LINK`, exit 1, то есть «OK» после правок настоящий,
просто покрытие уже ожидания.

**Вывод:** цена платилась не разовым протуханием, а непрерывным ремонтом — 55% коммитов.
Правило `doc-with-code` работает как заявлено и именно поэтому дорого.

## Граница проходит по выводимости, не по «код vs доки»

Тезис «достаточно кода» верен для всего, у чего есть **исполняемый оракул**, и неверен для
трёх классов, которые в коде невыразимы:

- **ратифицированные решения владельца с датами** (релаксация one-statement ceiling
  2026-08-27; `--today` внутри покрытия данных 2026-08-28);
- **измеренные причины выбора** — `maxLength` в схеме роутера убран, потому что он двигал
  `cov05` в multi-source clarification: 95/97 против 96/97, дважды, bit-for-bit;
- **намеренные удержания и non-claims** — «`RouterSplit`, multi-unit dispatch, concat merge
  удержаны намеренно, не удалять за отсутствием production-вызывающего»: из кода эта ветка
  читается ровно наоборот, как мёртвая.

## Что сделано в Greenplun

Удалены как дубль оракула: `CODE-MAP.md` (сам признавал `test_architecture_boundaries.py`
своей «executable copy»), `source-pipelines.md`, `observability-schema.md`,
`batch-artifact-schema.md` — схемы покрыты `tests/observability/` и `tests/batch/` (2921
строка). `ARCHITECTURE.md` переписан 252 → 134 строки: убраны диаграмма пути, таблица
владельцев, список удалённых модулей (его пиннит тест), продублированные в `GUARDRAILS.md`
effect ceilings; сохранено всё перечисленное выше невыводимое. Из `batch-artifact-schema.md`
спасён блок release authority в `eval-recipes.md`. В `AGENTS.md` пересказ дерева заменён
отсылкой к тесту, а порог devlog поднят: запись, пересказывающая собственный коммит, не
пишется — git log уже эпизодический журнал.

Оракулы: `project tracking: OK` (exit 0), `1679 passed, 15 skipped`.

## Независимая проверка поймала четыре потери

Правка — инвариант-сохраняющий рефактор, то есть silent-wrong класс, поэтому по §8 её
проверил кросс-вендорный ревьюер (Codex, `sandbox: read-only`, промпт на опровержение,
6 мин). Из пяти находок четыре воспроизвелись:

1. **`tests/test_architecture_boundaries.py` пиннит не весь удалённый набор.** В forbidden
   set есть splitter, temporal_classifier, candidate_selection, text2sql_runner и
   per-source compiler/policies/models — но **нет** `result_verifier`, `runtime.semantic`,
   `runtime.temporal_ir`, `runtime.text2sql_outcome`. Старый док нёс их списком; удалив его
   «как дубль теста», правка сделала утверждение «тест пиннит deleted set» ложным. Возврат
   любого из них прошёл бы зелёным. Это дефект самой правки, а не спорная находка.
2. «Изменение смысла существующего поля требует новой версии схемы» — код требует
   `schema_version == 1`, но same-version reinterpretation от легальной правки не отличает.
3. «Observation-код никогда не выводится из прозы/SQL/exception» — схема проверяет форму
   идентификатора, происхождение значения не проверяет никто.
4. «Заполнение счётчика не вызывает лишний producer-call» — запрет действия, которого код не
   совершает; отсутствие вызова не доказывает запрета.

Отклонена одна: матрица `GuardLifecycle × unit status` буквально лежит в
`schema.py` и там же валидируется — это код, а не проза (довод «реализация стала
единственным оракулом своего intended-контракта» не окупает 20 строк дубля).

Пункты 2–4 восстановлены блоком «Observability contract» в `GUARDRAILS.md` — 194 строки
схемы свелись к трём правилам, каждое из которых запрещает *действие*, а не значение;
такое типом и тестом не выражается. Пункт 1 — исправленным утверждением в `ARCHITECTURE.md`.

**Урок метода:** критерий «есть ли оракул» применяется к отдельному утверждению, а не к
файлу. Файл был прочитан целиком и всё равно потерял четыре строки — потому что решение
принималось про документ, а не про каждое его утверждение.

## Правка правила

Лаборатория — `rules/docs-discipline.md` rule #0 «оракул раньше прозы»; rule #1 обусловлен им.
Кит — v1.26.0: тот же rule 0, первые две строки mapping-таблицы routed в boundary-тест,
`CODE-MAP.md` переклассифицирован из контракта в навигационную помощь для репозитория с
неочевидной структурой.

## Порог

Формально это single-incident, и правило добавлено вопреки собственной дисциплине —
поэтому подпорки названы явно: (1) `docs/README.md` самого Greenplun **уже содержал** этот
принцип дословно («Истина о поведении — код и тесты… Документ, разошедшийся с кодом,
удаляется, а не актуализируется») — владелец пришёл к нему независимо, а объём всё равно
рос, то есть проза не самоисполняется; (2) кросс-проектная эмпирика
`continuity_format_friction` — тот же механизм с обратным знаком; (3) правка **снимает**
предписание, а не добавляет запрет, и цена ошибки асимметрична.

Не проверено: поведенческая проба в духе strip-revision кита — станет ли модель без rule #1
писать `ARCHITECTURE.md` при структурном изменении. Если да, rule #0 лишний и достаточно
ослабления rule #1.
