# Ротация sudo-audit.log: байтовый потолок вместо строчного

## Контекст

LOG-tier в `system-guard.sh` дописывал каждый sudo-вызов в `~/.claude/sudo-audit.log` без потолка — 1.5 МБ / 20888 строк за три месяца, единственная часть guard'а без ограничения. Наивная ротация «оставить последние N строк» оказалась не потолком вообще: команды логируются целиком, одна может быть 30 КБ.

Аудит начался с запроса «настроить конфигурацию Claude Code на Ubuntu». Конфиг оказался здоровым (20 ключей и 9 env-переменных валидны против бинаря через `strings`, файлы хуков на месте, git-гигиена `~/.claude` в whitelist-режиме), поэтому работа свелась к четырём точечным находкам.

## Изменения

**Ротация (F4).** Потолок в байтах: >1 МБ → обрезка до последних 256 КБ. Финальная форма прошла два раунда cross-vendor ревью (Codex через `codex_peer`, установка «опровергай») и вскрыла четыре реальных дефекта в собственной первой версии:

| Дефект | Источник |
|---|---|
| Лимит по строкам не держит байтовый потолок — 1.8 МБ переживали «ротацию» | Codex, подтверждён замером |
| `stat` не следует симлинку → возвращал 33 байта (размер линка), при симлинке ротация **не запускалась вообще** | main thread, при разборе ложно-зелёного теста |
| Байтовый разрез посреди многострочной записи → лог открывался обрывком. В живом логе 2009 строк на 173 записи с таймстампом — многострочные команды доминируют | Codex, подтверждён на живых данных |
| Утечка в stderr при неписуемой директории; порядок редиректов `>"$tmp" 2>/dev/null` сообщает провал открытия до глушения | Codex — он же поймал, что замер main thread'а этого был **невалиден** (лог успел обрезаться и не достигал ветки) |

Итоговый блок: пропуск симлинка (его цель — забота `logrotate` оператора), возобновление с первой полной записи через `sed`, глушение stderr до открытия временного файла, отказ от замены при пустом результате (одна запись шире окна → сохранить лог, а не обнулить след).

Два ограничения приняты осознанно: гонка двух хуков может потерять 1–2 строки (flock не окупает сложности), цепочка sudo-команд по >256 КБ обойдёт потолок.

**Изоляция тестов.** `LOG_FILE` стал переопределяемым через `CLAUDE_GUARD_LOG`. Тест-набор годами писал фабрикованные строки вроде `sudo -u root rm -rf /*` в боевой аудит-лог оператора — след, которому нельзя верить, хуже отсутствующего. Подменить `HOME` вместо этого нельзя: от него зависят deny-правила про `rm -rf $HOME`.

**Версионный разрыв (F1).** Claude Desktop несёт вкомпилированный CLI 2.1.197 (4 июля) при native CLI 2.1.247 — разрыв ~50 версий. Следствие, проверенное по бинарю: `workflowSizeGuideline` в глобальном `settings.json` **инертен в Desktop-сессиях**, ключа в 2.1.197 нет. Пакет ставился вручную из `.deb` и не зарегистрировал apt-репозиторий Anthropic, поэтому `apt upgrade` его не обновлял. Регистрация репозитория осталась за оператором (sudo).

**Диск (F3).** Удалены неиспользуемые версии CLI 2.1.243 и 2.1.245 — 734 МБ.

`DISABLE_TELEMETRY=1` не тронут по решению оператора; зафиксировано, что отдельного флага «телеметрия off, feature-flags on» в бинаре нет, то есть цена — недоступный Remote Control и тихо не включающиеся фичи под флагами.

## Затронутые файлы

- `~/.claude/hooks/system-guard.sh` — ротация LOG-tier, `CLAUDE_GUARD_LOG` (+29 строк; вне этого репо, глобальный слой)
- `.claude/benchmark/audit/test-system-guard.sh` — 17 новых кейсов ротации, глобальная изоляция лога через `CLAUDE_GUARD_LOG` (+81 строка)

## Проверка

```bash
bash .claude/benchmark/audit/test-system-guard.sh   # PASS=256 FAIL=0
```

239 исходных кейсов без регрессий + 17 новых. Каждый новый кейс проверен на способность падать: кейс «starts at a whole record» сперва прошёл до фикса (разрез случайно попал на границу записи) — генератор переписан на 200 continuation-строк на запись, после чего стал воспроизводимо красным.

Замеры вне тест-набора: худший случай ротации (лог у потолка, строки по 30 КБ) — 12 мс при бюджете хука 5000 мс; DENY-решение при переполненном логе не затронуто; прогон набора не меняет боевой `sudo-audit.log` (сверено по md5).
