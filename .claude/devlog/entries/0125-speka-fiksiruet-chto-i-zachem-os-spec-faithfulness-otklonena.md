# Спека фиксирует что и зачем; ось spec-faithfulness отклонена

## Контекст

Внешний бриф о спек-фазе («тонкая спека + CONTEXT.md наружу + вертикальные срезы + двухосевое ревью») на ~75% совпал с тем, что уже стоит в `WORKFLOW.md` §1-3 и `docs-discipline`. Триаж оставил 3 кандидата, и вместо адопта «по здравому смыслу» они прогнаны через A/B — 21 headless-прогон `claude --print --model opus` (CC 2.1.217), N=3 на рукав, детерминированные оракулы.

Отклонено без теста: `CONTEXT.md` (durable-слой уже вынесен в GLOSSARY/ARCHITECTURE/CONVENTIONS/ADR — новый store противоречит «один носитель»); формат запуска Input/Workflow/Output + «попроси `think`» (adaptive thinking ON by default, fixed budgets ретайрнуты — обвязка под неумение, которого нет).

## Изменения

**Д1 (детектор «что/зачем — явно; как — не фиксируй») + Д2 (ограничения = инварианты, `[hard]`/`[soft]`) — ADOPT.**
Проба A: одна стенограмма грилла → синтез PRD-lite; в грилл вшиты приманки-реализации, проговорённые оператором вскользь (`imported_rows`, индекс `(file_hash, row_no)`, `app/services/bank_import.py`, `pandas`).

| Рукав | утечек «как» (из 6) | бизнес-фактов (из 8) | hard/soft |
|---|---|---|---|
| A — текущий PRD-lite | 6, 6, 6 | 8, 8, 8 | нет |
| B — + Д1 + Д2 | 0, 0, 0 | 8, 8, 8 | да |

Полная сепарация, CV=0, guard-метрика не просела (класс регрессии из #113 — «правило вычищает факты вместе с нарративом» — не воспроизвёлся). Вред утечки не косметический: все утечки сели в *обязывающий* раздел «Ограничения», а в A-r3 реализационный ключ подменил acceptance-критерий («повторный запуск на том же файле — *тот же `file_hash`*» вместо идемпотентности по платежу). Смягчающее: в 2 из 3 прогонов модель сама пометила приманки как «гипотеза, не требование».

**Д3 (ось spec-faithfulness в ревью) — REJECT.** Ничья 3/3 на двух классах дефектов:
- проба B (дефект «пахнет»: нет атомарности на файл, R3 hard, тестами не ловится) — baseline сам нашёл `docs/SPEC.md`, привязал находки к номерам требований и подтвердил их исполнением кода;
- проба B2 (silent spec-defect: код чистый, 3 теста зелёные, коррекция не пишет аудит-след → R2/AC3 hard) — baseline 3/3, дословно «блокер приёмки по hard-ограничению R2».

Контрольный рукав C (тот же мандат, `docs/SPEC.md` удалён из репо): 0 упоминаний требований при том, что все код-смеллы найдены. Отсюда вывод, ради которого стоило добавлять рукав: **рычаг — спека как файл в репозитории, а не формулировка ревью-мандата**. Мандат кодировал assumption «модель не свяжет дифф со спекой», который неверен.

Д4 («вертикальные срезы, без путей к файлам в тикетах») не тестировалась — микро-дельта, поглощается формулировкой Д1.

## Проверка

- `bash .claude/benchmark/static-checks.sh` — 12/12 passed (Layer A).
- Оракулы валидированы на known-present needle (`imported_rows` виден в рукаве A, отсутствует в B); два ложных негатива грепа по `open_decision` найдены ручной вычиткой и исправлены до финального счёта.
- Seeded-дефекты верифицированы исполнением, а не чтением: частичный импорт остаётся закоммиченным (`in_transaction=False`), фикстуры зелёные 3/3 в обеих пробах.
- Прогоны изолированы вне репо (иначе подхватывается проектный `.claude/CLAUDE.md` лаборатории); глобальный `~/.claude/CLAUDE.md` активен в обоих рукавах как контроль.

Ограничения прогона: эмулирован *мандат* `/code-review`, не сам built-in skill; проба A мерит документ, не качество кода по нему; один домен, один язык спеки.
