# pipeline-ab: Pocock дороже в четыре раза при равном качестве

## Контекст

Оператор попросил сравнить поток, собранный по срезу #144, с актуальным
пайплайном Pocock в полноценном тесте. Стенд — `.claude/benchmark/pipeline-ab/`:
три brownfield-задачи на Python со скрытыми правилами владельца продукта
(NOTES) и скрытым оракулом; каждый человеческий ход играет симулятор с
заметками. Плечи: V ваниль, R поток по срезу (интервью → SPEC.md → приёмочные
тесты отдельной сессией → свежая сборка → ревью против спеки), P Pocock на
коммите `59db609` (`grill-with-docs` → `to-spec` → `to-tickets` →
`implement-spec`). Гипотезы и правила решения записаны в README до прогона;
27 прогонов на Opus, effort high.

## Что поймали дымовые прогоны (до основной матрицы)

- Симулятор, которому разрешено «продолжать», сам велел реализовывать на
  стадии спеки — оба пайплайна схлопывались в одну сессию.
- Даже без разрешения модель бралась за код во время грилла; в `-p` её некому
  прервать. Держит только механическая граница: deny на запись в `src/` и
  `tests/` плюс `chmod`. Словесное «только спека» не держит.
- Свежая сессия видит только файл: интерфейс, выпавший из SPEC.md, обнулил
  приёмку (0/38 из-за одной строки). Правило «интерфейс из запроса — в спеку
  дословно» внесено в `workflow.md`.

## Результат (детали — `RESULTS.md`)

- Качество: R и P — 100% приёмки в 9/9 прогонов, ваниль — в 5/9; медианы на
  T1/T2 у всех 100%, на T3 у ванили 89.5. По заявленному правилу H3
  пайплайн против ванили не подтверждён (≥10 п.п. только на одной задаче).
- Стоимость: R $2.7–3.6, P $11.3–14.1 — R дешевле на 71–77% при равном
  качестве, быстрее в 1.5–4.3 раза, человеку меньше ходов и текста.
  `implement-spec` запускал 12–22 субагента без прироста качества.
- TDD (H2): mutation score R ниже P на 0.004 / 0.043 / 0.072 — решение
  держится по правилу, но сдвиг однонаправленный.
- Ваниль добирала скрытые правила, перечисляя допущения в итоговом отчёте —
  внимательный симулятор их правил. Это смещение в её пользу.
- В R стадия Check — 41% стоимости, ревью нашло проблему в 1 прогоне из 9.

## Решения

Полный пайплайн Pocock по умолчанию не принимается; интервью до кода
остаётся; снятие TDD подтверждено. Какая часть R лишняя — добивающий тест с
«занятым» пользователем, который не правит итоговый отчёт (плечи V, S —
интервью и сборка в одной сессии, F — спека и свежая сборка без Check и
ревью, R), правило выбора заявлено в README до прогона.
