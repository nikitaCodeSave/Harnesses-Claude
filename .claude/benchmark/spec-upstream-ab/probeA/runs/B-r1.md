# Импорт банковской выгрузки в биллинг — PRD-lite

## Проблема
Ежедневную выгрузку платежей от банка бухгалтер разносит по счетам вручную.
Дважды за квартал банк присылал один и тот же файл повторно; в первый раз это
обнаружили только после жалобы клиента на двойное списание. Цена ошибки —
деньги клиента, поэтому главный риск не «долго», а «повторно списали».
Второй риск — PII: в выгрузке есть телефон клиента, инцидент с PII в логах
уже был.

## Пользователь
Бухгалтер. Видит, что файл появился, запускает импорт руками из CLI,
ждёт результата в консоли. Он же объясняет аудитору, почему по счёту
прошла та или иная проводка.

## Success (done)
1. Повторный запуск импорта на уже разнесённой выгрузке не изменяет остатки
   по счетам и не создаёт новых проводок; в отчёте видно «новых — 0».
2. Строка с уже известным идентификатором платежа, но другой суммой:
   прежняя проводка аннулирована, вместо неё создана новая, итог по счёту
   соответствует новой сумме.
3. По любой аннулированной проводке из публичного интерфейса можно получить
   кто, когда, какая сумма была и какая стала — в виде, который бухгалтер
   предъявляет аудитору.
4. Прерывание импорта на середине файла (сбой, kill) не оставляет ни одной
   проводки; повторный запуск после устранения причины разносит файл целиком.
5. При любом исходе — успех, отказ, необработанное исключение — телефон
   клиента отсутствует в выводе и логах любого уровня.

## Ограничения
- `[hard]` Импорт идемпотентен: результат определяется содержимым выгрузки,
  а не фактом и числом запусков и не именем файла.
- `[hard]` Атомарность на уровне файла: разнесён целиком либо не разнесён
  вообще. Частичный импорт хуже отсутствия импорта.
- `[hard]` Коррекция не переписывает прошлое: прежняя проводка аннулируется,
  новая создаётся рядом; история остаётся восстановимой.
- `[hard]` Телефон клиента не попадает в логи ни при каких обстоятельствах,
  включая трейсбеки и диагностический вывод по проблемной строке.
- `[hard]` Существующий API биллинга не изменяется.
- `[soft]` Прогресс выполнения виден в консоли, чтобы процесс не выглядел
  зависшим. Приятная мелочь, ею можно пожертвовать ради простоты.
- `[soft]` Объёмы — суточная выгрузка, не гигабайты; оптимизация под
  большой объём не требуется.

## NON-GOALS
- Автозапуск по событию из S3 — в первой версии только ручной запуск.
- Поддержка других банков и форматов выгрузки — формат один.
- Любые изменения существующего API биллинга.

## Открытое
- Строки, для которых счёт клиента в биллинге не найден: отбрасывать с
  отчётом или блокировать весь файл. Решение за оператором — от исполнителя
  ожидается предложенный вариант **с обоснованием**, а не молчаливый выбор.
  Учесть, что вариант «отбрасывать» ослабляет инвариант атомарности
  (файл считается разнесённым при неразнесённых строках).
