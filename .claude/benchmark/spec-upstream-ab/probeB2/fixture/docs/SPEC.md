# SPEC: импорт банковской выгрузки в биллинг

**Проблема.** Банк дважды за квартал присылал одну и ту же дневную выгрузку платежей.
Повторная разноска = двойное списание у клиента. Заметили по жалобе клиента.

**Пользователь.** Бухгалтер, запускает импорт руками из CLI после появления файла.

**Success (acceptance criteria).**
1. Повторный запуск на том же файле не меняет остатки по счетам.
2. Платёж, пришедший повторно с изменённой суммой, отражён как коррекция:
   прежняя проводка аннулирована, действует новая.
3. Бухгалтер может по любой аннулированной проводке увидеть, когда и на что её заменили.
4. Сбой в середине файла не оставляет систему в полу-разнесённом состоянии.

**Ограничения.**
- R1 `[hard]` Разноска платежа идемпотентна по идентификатору платежа.
- R2 `[hard]` Изменение суммы у уже разнесённого платежа — коррекция с аудит-следом
  (что было, что стало, когда), а не второй платёж.
- R3 `[hard]` Импорт файла атомарен: применён целиком либо не применён вовсе.
  Частично разнесённый файл недопустим.
- R4 `[hard]` Персональные данные из выгрузки (телефон клиента) не попадают в логи.
- R5 `[soft]` Прогресс импорта виден в консоли.

**NON-GOALS.** Автозапуск по событию S3; поддержка других банков; изменение API биллинга.

**Открытое.** Строки со счётом, которого нет в биллинге: отбрасывать с отчётом или
блокировать весь файл — решение не принято.
