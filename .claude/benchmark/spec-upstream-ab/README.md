# A/B: upstream-дельты спек-фазы (что/зачем vs как · hard/soft · spec-faithfulness)

owner: nikitaCodeSave
last-updated: 2026-07-22
status: experiment

Эмпирическая проверка трёх дельт, отобранных триажем брифа о спек-фазе
(остальные пункты брифа — HAVE или REJECT, см. devlog).

| Дельта | Куда метит | Проба |
|---|---|---|
| Д1 детектор «что/зачем — явно; как — не фиксируй» | `WORKFLOW.md` §2 (PRD-lite) | A |
| Д2 «ограничения = инварианты, не шаги» + `[hard]`/`[soft]` | `WORKFLOW.md` §2 (PRD-lite) | A |
| Д3 ось spec-faithfulness в ревью | `WORKFLOW.md` §REVIEW / `.claude/docs/workflow.md` | B |

Д4 («вертикальные срезы, без путей к файлам в тикетах») — не тестировалась:
микро-дельта, полностью поглощается формулировкой Д1.

## Общий дизайн

- Изменяется **ровно одна переменная** на пробу: рукав A = текущее состояние
  harness'а, рукав B = A + дельта. Всё остальное (вход, каркас, модель, cwd)
  идентично.
- `claude --print --model opus`, N=3 на рукав (Layer D, `.claude/docs/benchmark.md`).
- run-dir'ы — **вне репо** (scratchpad), иначе подхватывается проектный
  `.claude/CLAUDE.md` лаборатории и загрязняет обе ветки харнесс-контекстом.
  Глобальный `~/.claude/CLAUDE.md` подхватывается в обоих рукавах (контроль).
- Оракулы **детерминированные** (grep-скоринг + ручная верификация), не LLM-судья.

## Проба A — синтез спеки из грилла (`probeA/`)

Вход: `grill-transcript.md` — стенограмма грилл-сессии по задаче «импорт банковской
выгрузки в биллинг». В неё намеренно вшиты **приманки-реализации**, проговорённые
оператором вскользь и неавторитетно («наверное», «я бы»): таблица `imported_rows`,
уникальный индекс по `(file_hash, row_no)`, путь `app/services/bank_import.py`,
библиотека `pandas`.

- Рукав A: каркас PRD-lite как в `WORKFLOW.md` §2 (+ секция «Ограничения», чтобы
  секция была в обоих рукавах и переменная осталась одна).
- Рукав B: то же + Д1 + Д2.

Метрики (`score.py`):
- `impl_leaks` 0–6 — сколько приманок утекло в спеку (**ниже лучше**);
- `facts_kept` 0–8 — guard: сколько обязательных бизнес-фактов сохранено
  (дельта не должна стоить фактов — контроль на класс регрессии из devlog #113);
- `hard_soft` — descriptive.

## Проба B — spec-faithfulness в ревью (`probeB/`)

Фикстура `probeB/fixture/` — git-репо: `docs/SPEC.md` (R1–R5 с hard/soft),
реализация и 3 **зелёных** теста. Base-коммит содержит стаб
(`base-bank_import.py`), рабочий дифф = реализация.

Seeded-дефекты:

| ID | Что | Нарушает | Пахнет сам по себе? |
|---|---|---|---|
| **D1** | нет атомарности на файл: `conn.commit()` внутри цикла по строкам | R3 `[hard]` | **нет** (тесты зелёные; verified: при падении на 2-й строке первая остаётся закоммиченной, `in_transaction=False`) |
| **D2** | телефон клиента в `log.info` | R4 `[hard]` | да (PII) |
| **D3** | SQL-инъекция через f-string | — (вне спеки) | да — контроль, что оба рукава вообще ревьюят |

- Рукав A: «проведи ревью рабочего диффа, найди проблемы» (аналог `/code-review`).
- Рукав B: то же + вторая ось spec-faithfulness с `docs/SPEC.md` как оракулом.
- Рукав C (`run-c.sh`, добавлен после ничьей A vs B): мандат рукава A, но `docs/SPEC.md`
  из репо удалён — отделяет эффект мандата от эффекта наличия спеки-файла.

Спека лежит в репо в рукавах A и B — мерится эффект мандата, не доступа к файлу.

## Проба B2 — Д3 на silent spec-defect (`probeB2/`)

Проба B оказалась нечувствительной: D1 «пахнет» и находится без спеки (рукав C).
B2 — та же схема на дефекте, который из кода как дефект **не читается**.

Фикстура: реализация корректна (атомарность на файл есть, SQL параметризован,
PII в логи не течёт), 3 теста зелёные. Единственный seeded-дефект — **D4: коррекция
не оставляет аудит-следа** (нет ни таблицы, ни поля времени/ссылки на замену),
что нарушает R2 `[hard]` и AC3. Отсутствие того, чего нет, смеллом не выглядит.

Рукава — как в пробе B (A: обычный мандат; B: + ось spec-faithfulness), спека
в репо в обоих.

## Как прогнать

```bash
bash probeA/run.sh <runs_root> 3 && python3 probeA/score.py <runs_root>/*/out.md
bash probeB/run.sh <runs_root> 3 && python3 probeB/score.py <runs_root>/*/out.md
```

Результаты прогона 2026-07-22 — `RESULTS.md`.
