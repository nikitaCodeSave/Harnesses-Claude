# 3. Кит отгружает команды потока; обвязка проекта растёт проектными скиллами

Дата: 2026-10-29 · Решение оператора

## Context

Кит ставил в проект короткий `CLAUDE.md` с блоком *How we work*, а измеренные промпты (интервью →
спека → сборка, тесты по тикету, сборка по тестам, ревью против спеки, разбор находок) оператор
вводил руками по мануалу. На стенде каждую стадию запускал оператор отдельной строкой; следует ли
сессия блоку без неё — не измерено. Оператор: «не должен теряться в начале сессии и при попытке
разобраться с новой задачей». Отдельно — продакшн-проекту нужна обвязка, которая растёт вместе с
ним: процедура, найденная долгим поиском, должна становиться скиллом проекта.

## Decision

- Плагин `harness` отгружает команды, которые вызывает только пользователь
  (`disable-model-invocation: true` — в контексте модели их нет, пока не введены):
  - `start` — маршрутизатор по состоянию репозитория, включая скиллы Pocock;
  - `task`, `bugfix`, `tests`, `build`, `check`, `wrap` — шаги потока с измеренными промптами;
  - `skill`, `trajectory` — выращивание проектных скиллов из решённых задач и сокращение их
    траекторий.
- Скиллы Pocock для обсуждения (`/grill-with-docs`, `/grill-me`, `/to-questionnaire`,
  `/wait-what`) встроены в маршрут `start` и мануал как вход до `task`.
- При установке скиллы в проект не ставятся: проектный скилл появляется из задачи, которую проект
  решил, — это то же правило, что «action-skill — под повторяющуюся операцию без встроенного
  аналога».

## Consequences

- Оракул кита — механическая проверка M8: каждая команда user-invoked, и каждая упомянутая
  `/harness:<имя>` существует.
- Эффект команд против одного `CLAUDE.md` не измерен; дымовые прогоны `start`, `task`, `check`
  записаны в CHANGELOG кита (3.1.0). Кандидат на стенд: поведенческое сравнение «кит без команд»
  против «кит с командами» на задачах `pipeline-ab`.
- Помощники для скиллов (`skill-conductor`, `developing-ai-agents`) — опции в мануале, не
  зависимость кита.
